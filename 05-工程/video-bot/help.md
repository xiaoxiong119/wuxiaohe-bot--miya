**视频 → 分秒帧（两条命令，别用混）**

- `/upmedia 名字` —— 传**聊天框里**刚发的那个视频。例：先发视频，再发 `/upmedia 67`
- `/driveup 名字` —— 传**云盘收件夹**（{{DRIVE_FOLDER_URL}}）里的文件，不用发到聊天框。例：`/driveup test文件`（能匹配 `test文件.mov`）

聊天框发来的视频超过 100 MB 会被飞书挡住，这种就走 `/driveup`。
- 机器人把视频传到{{TARGET_LABEL}}，并重命名成 `67.mp4`
- 不带扩展名就沿用原视频的；名字里的 `/ \ : * ? " < > |` 会换成 `_`
- 命令先发也行：发完等 5 分钟内的下一条视频
- 连发多个视频会排队，`/upmedia` 每次取最早那条
- **多人同时传也不打架**：机器人一次只传一个，后面排着的会收到「前面还有几个、大概几分钟」的提示，不用重复发；单个文件卡住超过 45 分钟会自动放弃，接着传下一个，不会把整条队列堵死
- **同名自动升版本**：传同名文件不会多出一份，会走分秒帧的「上传版本」把 v2/v3 顶上，**不会产生重复文件**。举个例子：上一次传的是 `/upmedia 70`，这一次就还是 `/upmedia 70`
- **改版文件名自动归一**：云盘里叫 `122-改.mov`、`54集-修改版.mp4`、`122-final.mov` 这种带修改标记的，机器人按这一集的原名（`122.mov`、`54集.mp4`）传，还是走「上传版本」更新那一条，**不会另开一份新文件**。认得「改 / 修改 / 改版 / 修改版 / 重改 / 再改 / 修订 / 修正 / 定稿 / 终稿 / final / rev / fix / v2」这些写法；`57-2.mp4` 这种分卷不算改版，名字原样保留
- **扩展名不一样也能认**：列表里是 `122.mov`、这次传的是 `.mp4`，也会挂到 `122.mov` 上走「上传版本」，不会再并排多一份
- **上传成功自动改表**：名字里带集数的（如 `113`、`7-修改`），传完自动把多维表格该集的「素材生成进展」记为 **已粗剪待一审**，并给审片人重发一审卡片；已经「已完成并上传/已定剪」的集不回退

**大文件（超过 100 MB）**

飞书消息里的附件最大只能下 100 MB。大文件走共享云盘文件夹：

- 设文件夹：`/drive https://<租户>.feishu.cn/drive/folder/<token>`
- 传指定文件：`/driveup 文件名`
- 手动全扫：`/drive`（自动扫描当前是关的，想开说一声）
- 同事把视频丢进那个文件夹就行，文件名就是分秒帧里的名字（`71.mp4` → `71.mp4`）
- 文件名带「-改 / -修改版 / -final」这类修改标记的，按这一集原名传（`122-改.mov` → `122.mov` 的 v2），不会多出一份
- 机器人下载 → 传到分秒帧 → 临时文件删掉，本地不留东西
- 前提：文件夹把「乌小河」加为可阅读；应用要有 `space:document:retrieve`

其他两条：

- 本地投递箱（只在你自己电脑上时用）：`~/WorkBuddy/乌小河机器人/05-工程/video-bot/inbox/`，丢进去 10 秒自动传
- 单个文件链接：`/upmedia 67 <文件链接>`，前提同样是分享给机器人

**批注同步到多维表格（/tbpz）**

把分秒帧上视频的批注搬到多维表格（一条批注一行）。**只发 `/tbpz` 不动手，只回用法**——要写明跑哪一路。

粗剪批注（主用，配置在 `reviewSync`）：

- `/tbpz 粗剪` —— **增量同步**：只读上次同步之后更新过的视频，外加右上「消息通知」里刚被批注的视频（批注不会刷新视频的更新时间，靠这条兜住老视频上的新批注），读完写表
- `/tbpz 粗剪 全量` —— 不看水位，滚完整张视频列表再同步（久，几分钟到十几分钟）
- `/tbpz 粗剪 预览` —— 增量只读不写；`/tbpz 粗剪 全量预览` —— 全量只读不写
- `/tbpz 粗剪 配置` —— 看当前的分秒帧链接、多维表格链接、表 id
- `/tbpz 粗剪 分秒帧 <项目链接>` —— 换批注来源
- `/tbpz 粗剪 表格 <表格链接>` —— 换写入的表（wiki 或 base 链接，要带 `?table=`，可带 `?view=`）

精剪批注（独立备份表，配置在 `reviewSyncFineCut`）：

- `/tbpz 精剪 中断`（或 `/tbpz 中断`）—— 在发起同步的会话停止采集或后续写入，保留缓存和已写记录，不推进增量水位；粗剪可发 `/tbpz 粗剪 中断`。全量及首次同步采集上限 120 分钟，普通增量 25 分钟。
- `/tbpz 精剪 写入` —— 直接写入最近一次精剪预览缓存，不重新打开分秒帧；写前查表去重，可重复执行。目标变更后须重新预览；不完整缓存仅写已采集部分，不推进增量水位。
- `/tbpz 精剪` —— 同步精剪视频批注到精剪备份表，首次全量、之后独立增量
- 同样支持 `预览` / `全量` / `全量预览` / `配置` / `分秒帧` / `表格`

旧写法 `/tbpz 预览`、`/tbpz 全量`、`/tbpz 全量预览`、`/tbpz 执行`、`/tbpz 分秒帧 …`、`/tbpz 表格 …` 仍然按粗剪执行，不会报错，但回执里的说明会写成新样式。

写进表的字段：集数 / Timeline / 需求简述 / 批注日期。
去重：同集 + 同时间点只写第一条（后面的多是回复）；表里已经有的按「集数 + 时间点 + 原文」跳过。
一轮跑完会回报读了几个视频、写了几条；同步台账记在 `tbpz-sync-log.jsonl`，增量水位 `lastSyncAt` 存在 config.json 的 `reviewSync` 里；精剪分支独立存于 `reviewSyncFineCut`，台账带分支及目标。

实测状态：能用，但依赖本机 Chrome + bsk（分秒帧没有开放接口，只能驱动网页读），一轮要几分钟；同一时刻只跑一轮，跑着的时候再发会回「已经在跑了」。

**改多维表格**

- `/base 把 70 集的素材生成进展改成已上传`
- 能认的字段：素材生成进展 / 进展 / 审阅反馈 / 剪辑进度 / 二轮审阅反馈

**审阅流程（自动）**

- 到开始日期且进展=待开始 → 自动置「进行中 / 生成中」
- 素材生成进展=已粗剪待一审 → 自动发一审卡片（只发给审片人；剪辑师等一审通过、素材上传后才介入）
- 卡片按钮：查看粗剪 / 一审通过 / 一审未通过
- 一审通过 → 审阅反馈=通过、剪辑进度=可剪辑 → 通知制作师上传素材
- 一审未通过 → 审阅反馈=**有修改**、素材生成进展=**修改中** → 通知制作师修改（已是有修改时不再重复通知）
- **点了按钮会回执**：这一步要是给别人发了卡（制作师/审片人/剪辑师），机器人回你一句「✅ 已通知到 张三（审片人）：…」
- **点错了能撤回**：点完按钮，**只有被点的那个按钮**变成「↩︎ 撤回」，同一张卡上别的按钮照常能点（点「开始剪辑」后还能点「精剪完成」）。点撤回 = 字段改回去 + 这张卡复原成点的样子；已发出去的通知收不回
- 「开始精剪」卡片要三个条件同时成立才发：剪辑进度=可剪辑、素材生成进展=已完成并上传、审阅反馈=通过（谁先谁后都行，齐了就发，每分钟巡检会补发）
- 剪辑师点「开始剪辑」→ 剪辑进度=剪辑中；点「精剪完成」→ 剪辑进度=待审片 → 通知审片人终审
- 审片人点「查看成片」→ 跳分秒帧，同时剪辑进度=审片中；点「剪辑通过」→ 已定剪 + 进展=已完成 + 回填实际完成日期

**整点体检**

- 工作日 10:00-19:00，每个整点给你发一张体检卡：多维表格读表、表格自动化巡检、今天 8:30 自检结果、bsk、分秒帧目标、下载目录、长连接、最近一次上传
- 全绿是绿卡；任何一项不对劲变红卡，标 ✗ 的那条直接说原因
- 红卡上有个「**通知小熊重启机器人**」按钮，**谁都能点**：点了我会给你发一张「通知重启」卡——坏的是哪个功能、最近的错误日志、谁反馈的，卡片上有「重启机器人」按钮让你一键重启

**版本更新公告（手动）**

- **先预览再发送**：乌小熊私聊发 `/release`，机器人先返回公告示例卡；点击「发送到（群聊名）」后，群里才收到不带操作按钮的公告。
- 可点「修改公告内容」，手动编辑标题、正文，点「保存并预览」，确认后再点发送；保存不会发群。
- 草稿会保留，重启后再次私聊 `/release` 可恢复；旧预览失效，已发送的公告不能重复点击发送。
- `/release status` —— 看现状：线上版本、已记录版本、待发布几条改动、公告发到哪个群（不往群里发东西）

- `/公告群 逆天萌兽制作组` —— 换公告群（不带名字就列出我在的所有群）
