# /tbpq 排期同步（测试项目）

命令 `/tbpq` 执行同步，`/tbpq 预览` 只读检查。源为《逆天萌兽》资产的「第二季排期」aCHsjd，目标为 TOaybhQEGayFLfsxh5wccrGBn3b / [已脱敏]；配置在 config.json 的 scheduleSync。不使用正式任务表作为写入目标。

一条源排期分段对应目标一行，数字「集数」之外增加文本「排期分段」保留第23集-1、第23集-2等标识。只写集数、排期分段、场景、制作师、开始日期、预计完成日期；不改状态、审片人或剪辑师。新增行可能继承目标表已有默认值。

颜色映射通过源表中的姓名简称和正式任务表真实人员 ID 交叉核实。10月16日 G 列为“调整修改/围读”，整列红底不代表分配给陈俊杰。普通日期中即使色块没有文字，仍代表当天的制作排期。日期按配置的2026年、上海时区零点写入；修改日和交付日列不充当人员分配。

场景只继承真实合并单元格，不把任意空白向下填充。部分源场景为空且没有分段的集数，使用2026-10-29已核实的正式任务表场景补全，来源记在每次审计 JSON 的 sceneBasis 中；直接写在源表中的场景优先。第64集-1、64集-2的场景无法确定各段对应关系，按用户“不用管”的要求留空，不反复提示。

人员通过 OpenAPI 字段写入，不操作网页通知选项，不调用 IM，也不挂入正式审阅流程。每轮写入前检查目标 Base 没有工作流，发现工作流即中止，避免间接通知。目标测试表新增记录的现有默认字段不由本命令设置。

以「排期分段」匹配，重复同步只更新变化的字段；未出现在源表的目标行不删除。颜色未知、同段多人、目标分段重复、目标存在无法安全归属的旧记录、源读取不完整或字段类型不符时中止。飞书把数字主字段以字符串返回，比较时按数字统一，避免每次运行重复更新。

日志：logs/tbpq-*-preview.json、logs/tbpq-*-sync.json。包含源版本、源单元格、人员、场景依据、完整目标字段和回读验收状态。首次测试写入136行，对应129集，七集各有两段；全量回读一致，重复执行新增0、更新0、不变136。
