```

```

**共同硬限制**：都跑在这台 Mac 上，关机 / 休眠 = 机器人失联。

## 三条主链路

### 1. 视频 → 分秒帧（当前主线）

`05-工程/video-bot/`，跑在新应用 `[已脱敏]` 上：

```
发视频 → 机器人缓存，回「要传的话发 /upmedia 名字」
发 /upmedia 67 → 下载 → 落盘命名 67.mp4 → 子进程 bsk 上传 → 回「列表 N→N+1 + 项目链接」
```

命令先到也行（等 5 分钟内的下一个视频）。不起 WorkBuddy 会话，不吃 token。

### 2. 文档 / 表格 / 周报（历史应用的能力）

飞书里发链接或斜杠命令 → agent 用 `lark-cli` 直接读 → 回结论或建文档。

- wiki 链接要先 `lark-cli drive +inspect --url` 解包成真实 token
- 多维表格的参数是 `--base-token`，不是 `--app-token`
- 改完文档必须 `docs +fetch` 读回确认

新应用要接这套，得先开文档权限（见 `03-权限/开通链接.md`），再把飞书通道切过去。

### 3. 多维表格自动化

`05-工程/base-notify/`：一个挂在历史应用下的插件，表格自动化触发时把消息发到指定人/群。

改它之前先读同目录 `README.md`：登录、编译、上传、后台配置、11 条踩坑都在里面。

## 硬边界（绕不过，别硬试）

1. **电脑要开着。** 合盖休眠，机器人就不干活。
2. **群聊必须 @ 它**（仅历史应用走 WorkBuddy 通道时；新机器人收群消息由 `config.json` 的 `allowGroups` 控制）。
3. **单文件 ≤ 100 MB**（`im.v1.messageResource.get` 限制）。更大的先压缩或分卷。
4. **分秒帧没有上传 API**，只能靠本机 Chrome 的登录态驱动网页。登录过期就传不了。
5. **同名文件不覆盖**，分秒帧会并存两份。
