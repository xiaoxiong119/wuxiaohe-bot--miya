## 一、飞书里发消息没反应

按这个顺序查，命中即停：

| # | 检查 | 命令 / 位置 | 结论 |
| --- | --- | --- | --- |
| 1 | WorkBuddy 是否在跑 | 菜单栏图标 | 退出 = 长连接断 = 机器人失联 |
| 2 | 通道是否启用 | `status.sh` 的【通道】段 | `enabled=false` 就去客户端重新连飞书 |
| 3 | 群里是不是没 @ | `replyPolicy = mention` | 群里必须 @乌小河 |
| 4 | 应用可用范围含不含你 | 开放平台 → 版本管理与发布 → 可用范围 | 不含就加人再发版 |
| 5 | 事件订阅是不是「长连接」 | 开放平台 → 事件与回调 | 选成 webhook 就没推送 |
| 6 | 版本是否发布 | 开放平台 → 版本管理与发布 | 草稿态不生效 |
| 7 | 会话是否被 `lark-cli event consume` 抢走 | `lark-cli event status` | 同一个应用只能有一个稳定消费者 |

## 二、视频转存不动

### 2.0 先分清是哪套

| | 当前（新应用 `[已脱敏]`） | 历史（`[已脱敏]`） |
| --- | --- | --- |
| 代码 | `05-工程/video-bot` | `05-工程/video-to-mediatrack` |
| 收消息 | 长连接直收 | 每 8 秒轮询 |
| 启动 | `video-bot/start.sh` | `video-to-mediatrack/start.sh` |
| 日志 | `video-bot/logs/bot.log` | `video-to-mediatrack/logs/daemon.log` |

**两套不能同时跑**，否则同一个视频传两遍。

### 2.0.1 新机器人常见的三种不动

| 现象 | 原因 | 解 |
| --- | --- | --- |
| 发视频完全没反应，日志无新行 | 应用没开 `im:message.p2p_msg:readonly` / 没订阅 `im.message.receive_v1` / 版本没发布 | 按 `03-权限/开通链接.md` 开权限，事件订阅选长连接，再发版 |
| 日志有「收到 …，正在上传」，然后卡住 | bsk 没起，或分秒帧登录过期 | `bsk status --json`；过期就扫码重登 |
| 回了「❌ 下载失败：Request failed with status code 400」 | **缺 `im:message:readonly`**。`im:resource` 只代表「允许碰附件」，读某条消息里的资源还要消息读取权限 | 开 `im:message:readonly`（普通，即时生效）：`https://open.feishu.cn/page/scope-apply?clientID=[已脱敏]&scopes=im%3Amessage%3Areadonly` |
| 回了「❌ 下载失败」，附了别的 code | 文件 > 100 MB / file_key 过期 / 权限没发版 | 看日志里的飞书 code；>100 MB 只能压缩分卷 |

### 2.1 daemon 没起（历史链路）

```bash
cd ~/WorkBuddy/乌小河机器人/05-工程/video-to-mediatrack && ./start.sh
```

`start.sh` 用 Python 的 `start_new_session=True` 拉起进程，脱离 WorkBuddy 的进程组。
**不要用 `nohup`、不要用 `&`、不要在 WorkBuddy 会话里后台起**——都会被回收。

### 2.2 daemon「假活」

现象：`daemon.log` 每隔 8 秒刷一行「初始化：已有 0 条视频」，但什么都不做。

原因通常是 bsk socket 残留：

```bash
rm ~/.bsk/run/daemon.sock
cd ~/WorkBuddy/乌小河机器人/05-工程/video-to-mediatrack && ./start.sh
```

这个 socket 文件在 WorkBuddy 会话里删不掉（权限策略拦），必须小熊在终端敲。

### 2.3 launchd 起不来

`launchctl bootstrap` 报 `error 5`，plist 用 `plutil -lint` 却是好的。
根因没坐实，最可能是路径里带中文（`通用`／`乌小河机器人`）导致加载失败。

**现状**：不依赖 launchd，手动开终端跑 `./start.sh`。合盖休眠后需要重新起。

### 2.4 上传报「登录已过期」

本机 Chrome 里的分秒帧登录态过期。打开 https://app.mediatrack.cn 扫码重登，再重发一次。

### 2.5 上传报「Not allowed」/ 注入文件失败

Chrome 扩展权限没开：`chrome://extensions` → bsk 扩展 → 打开「允许访问文件网址」。

### 2.6 上传成功但列表数没变

同名文件不覆盖，分秒帧会并存两份。脚本靠「共 N 项」计数判断成败，计数没变就是没成功，
去页面确认，别信文件名。

## 三、飞书接口报错

| 报错 | 原因 | 解 |
| --- | --- | --- |
| `99991668 user access token not support` | 应用级接口用了 user 身份 | 加 `--as bot` |
| `10014 凭证无效` | App Secret 错 | 重新填 |
| `230027` 读群消息被拒 | bot 身份读群历史受限 | 脚本里已做 user 身份回退 |
| `230013 / 230002` | 机器人不在群里 / 群 id 错 | 拉进群或改 chat_id |
| `messageResource.get 400` | 文件 > 100 MB | 压缩或分卷，接口硬限制 |

---

## 四、身份与权限的坑

- **两套令牌**：`tenant_access_token`（应用身份，权限小）和 `user_access_token`（你本人，权限大）。
  查应用自身信息（scopes、slash commands 列表之外的 app 详情）必须应用身份。
- **斜杠命令**走用户身份（lark-cli 默认），别加 `--as bot`。
- 凭证在钥匙串：`appsecret:[已脱敏]`。settings.json 里是加密 envelope，抄不出明文。

---

## 五、事件的坑

- **长连接 3 秒超时**：飞书要求 3 秒内响应，超时会重推同一事件。所有重活必须入队/异步，
  并靠 `state.json` 的 `message_id` 去重（新链路 video-bot 已经这么写）。
- **事件独占**：同一个应用起两个消费者，飞书会把事件随机分给其中一个 → 丢失。
  要接 `card.action.trigger` 就另建一个应用，别跟主链路挤。
- **`create_time` 只精确到分钟**：判断消息新旧不能用时间戳，要用 `message_id` 集合（踩过）。

## 六点五、每日体检（999 测试集）

每个法定工作日 08:30 的定时任务会跑 `05-工程/video-bot/scripts/selftest-999.js`，跑完往陈俊杰飞书私聊发一条 `✅/❌ 每日体检…`。

| 症状 | 先看 | 常见原因 |
| --- | --- | --- |
| 早上没收到体检报告 | `logs/selftest-log.jsonl` 有没有今天的行 | ① 今天不是法定工作日（脚本主动跳过，不发消息）；② 定时任务被停/改；③ 机器人进程没起且 `start.sh` 失败 |
| 同事看到红卡点「通知小熊重启机器人」后没下文 | `grep 通知小熊 logs/bot.log` | 卡片应该立刻到小熊私聊；没到说明 `inbox.notifyOpenId` 配错或发卡失败。反馈人那边的 toast 只是「已通知」 |
| 体检卡是红的、想一键重启 | 直接点卡上的「重启机器人」 | 机器人自停自起，约 30 秒后把新的体检卡发回原会话。没按钮说明是全绿；别人点了会被挡（只有陈俊杰能点） |
| 点了重启但没人回 | `logs/restart.log`、再看 `bot.pid` 有没有换新 | 多半是 start.sh 卡住（bsk 没起 / 旧 daemon 还在）。手动 `./stop.sh; ./start.sh` 看输出 |
| 报告里「待一审卡片由巡检自动发出」✗ | `grep '②自动化' logs/bot.log` | 去重键卡住（正常不会再发生，见 2026-10-28 的 `seen` 机制）、或审片人字段为空 |
| 报告里某个按钮步骤 ✗ | `logs/bot.log` 对应时间点的报错 | 多半是字段选项值对不上（比如「剪辑进度」写 `审片中`、`可剪辑`，表里被删了选项就会 400）、或该字段被表结构改过 |
| 报告里「机器人自动置…」✗ | `grep '①自动化' logs/bot.log` | 开始日期没写进去（时区/日期字段类型变了）、或巡检被关（`config.flow.enabled`） |
| 工作日判断老是 fallback | `ls logs/holiday-cn-*.json` | 三个数据源都不通；缓存 7 天，能连通时会自动落盘 |

想手动跑一次（忽略工作日判断）：`cd 05-工程/video-bot && node scripts/selftest-999.js --force`。
