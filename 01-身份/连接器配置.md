## 通道（WorkBuddy 侧）

飞书消息由 WorkBuddy 客户端接管，不是这个目录里的代码在收。配置在
`~/.workbuddy/settings.json` → `claw.users.<uid>.channels.feishu`：

| 配置 | 值 | 影响 |
| --- | --- | --- |
| `enabled` | true | 通道开 |
| `connectionMode` | `websocket` | 长连接，不需要公网地址 |
| `replyPolicy.mode` | `mention` | **群里只有 @ 乌小河 才会回**，私聊不受限 |
| `appId` / `appSecret` | 加密存储（envelope） | 写入时可以给明文，客户端会自己 seal |
| `encryptKey` / `verificationToken` | 空 | 长连接模式用不到 |

> 凭证是 WorkBuddy 加密存储的，别试图从 settings.json 里直接抄明文——抄不出来，也不该抄。
> 要用应用凭证调接口，走 `lark-cli`（凭证在钥匙串，`appsecret:[已脱敏]`）。

### 通道配置丢了怎么恢复（2026-11-02 实操验证）

背景：飞书通道配置被删空过（`channels` 里只剩微信），界面上加回来要手填 secret。

关键发现：**`appSecret` 不用解密 WorkBuddy 的信封**——直接往 `settings.json` 写明文，
WorkBuddy 检测到文件变化会读进来、当场 `seal` 成 `$wbEncrypted` 并回写。读取侧
`decodeString` 对普通字符串是原样返回（`typeof e === 'string' ? e : open(e)`），所以明文合法。

步骤：

1. 备份 `cp ~/.workbuddy/settings.json ~/.workbuddy/settings.json.bak-<日期>`
2. 往 `claw.users.<uid>.channels` 写：

```json
"feishu": {
  "enabled": true,
  "connectionMode": "websocket",
  "appId": "[已脱敏]",
  "appSecret": "<见下>",
  "encryptKey": "",
  "verificationToken": "",
  "replyPolicy": { "mode": "mention" }
}
```

3. 存盘后几秒内，`appId` / `appSecret` / `encryptKey` / `verificationToken` 四个字段
   会自动变成 `{"$wbEncrypted":1,"envelope":"…"}`（keyId `9127dea1b44020a7`）。变了就说明客户端认了。
4. 重启 WorkBuddy 让长连接重新建立。

**appSecret 从哪取**：lark-cli 自己加密存在 `~/Library/Application Support/lark-cli/appsecret_cli_<appid>.enc`，
格式是 `nonce(12) | ciphertext | tag(16)`，AES-256-GCM，key 是钥匙串 `lark-cli` / `master.key`
（值形如 `go-keyring-base64:<base64>`，解码一次得到内层 base64，再解一次得 32 字节 key，两次都无 AAD）。
2026-11-02 用这个方法取出的 secret 已用 `tenant_access_token/internal` 验证有效。

> 别把 secret 明文写进任何仓库文件。要填就现场取。

export PATH="$HOME/.local/bin:$PATH"
