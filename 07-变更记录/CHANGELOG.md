## 2026-10-29 · 并发任务三处加固（同名下载 / 排队体验 / 单实例）

- **同名并发下载不再互相覆盖**：新增 `src/tempfile.js`，每次下载单独开 `.t-<时间戳>-<tag>/` 子目录，文件名仍是目标名（worker 按 basename 认分秒帧条目，不影响「上传版本」）。以前 `/driveup` 和云盘链接直接写 `downloads/<目标名>`，两个人同时传同一集（`122-改1` / `122-改2` 都归一成 `122.mov`）会同时写一个文件，可能传上去半截。`runJob` 改为所有自下载任务都走临时目录，传完连目录一起收；`cleanOldDownloads` 顺手清 3 天前的任务目录。
- **排队可见**：`enqueue` 算「前面还有几个」，回一句「⏳ 已排队：前面还有 N 个文件，预计 X 分钟后轮到你」。估时取最近 20 次成功上传耗时的中位数（`state.durations`，默认 3 分钟）。
- **轮流传，不让人饿死**：新增 `src/queueorder.js`，队首和刚传完是同一个人、后面还排着别人的，就先让别人的上；同一个人的几条之间顺序不变，系统任务（云盘投递/投递箱）不参与让位。
- **队列不会再被一个卡死的任务锁死**：`pump` 的收尾全部挪进 `finally`（原来 catch 里回消息再出错就 `busy` 永久为 true）；`runWorker` 加单个文件 45 分钟上限（`UPLOAD_TIMEOUT_MIN` 可调），超时 SIGTERM 整个进程组、10 秒后 SIGKILL，报错后接着传下一个。
- **单实例锁**：新增 `src/lock.js`，`.bot.lock` 记 pid，`kill -0` + `ps` 命令行双重判活（防 pid 复用），旧锁/死锁自动接管；第二个实例启动即退出并提示先 `./stop.sh`。挡住「直接 `node src/index.js` 绕过 start.sh 检查」这条口子。
- help.md / help-lite.md 补一句排队与卡死自动放弃；`scripts/note.js` 记两条待发布。

## 2026-10-28 · 修下载慢：飞书 CDN 选路

- 现象：73.mov（56.8 MB）在飞书里下 16.5 分钟（~58 KB/s），但同一台机器 curl 同一接口能到 4 MB/s，测速网也正常。

  - 直连 IP 时用 `host=IP + servername=域名 + Host 头`（Node 22 的 `lookup` 回调和 autoSelectFamily 打架，会报 `Invalid IP address: undefined`）。
